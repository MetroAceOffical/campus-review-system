# 任务流程工作区、模型继续训练与全文审核重构设计

状态：用户于2026-10-31明确批准实施，包含BERT续训到实际审核链路；以下为已批准设计，不代表各阶段已经实现。

依据：10月31日用户明确要求整体重组前端、减少重复按钮、固定并贯穿真实流程、提高有效信息密度、支持已完成模型继续训练、审核全文对照和按当前配置复检。保留10月30日设计中的品牌、直角风格、角色、分页与历史追溯约束；以下要求优先于旧设计中仅以页面跳转连接模块的安排。

## 1. 目标及现状核对

让普通用户围绕一项具体任务完成操作，始终知道当前对象、所处阶段、结果与下一项操作。统一前端页面结构和组件，而不是在原有页面重复增加跳转入口。

已核对源码：

- `workflow-context.ts`主要在内存及URL保留数据、版本、任务和模型选择，尚无独立持久化的用户流程任务。
- `TrainingCheckpoints.inspect`仅允许失败、取消、中断的CNN/BiLSTM/BERT恢复；`training_resume.py`要求原数据、划分、参数、代码及环境身份相同。已完成模型的权重继续训练尚未实现。
- 一个数据集当前可以重复创建多次训练、训练多个算法；真正缺失的是从已完成模型权重继续优化，并在同一逻辑模型下管理版本。
- `InspectionService.submission`和现有`/api/submissions/{id}/checks`已经支持从不可变送审快照创建CONTENT检查；可复用其能力建设正式稿件的复检入口，无需新上传文章或覆盖旧检测批次。
- 正式`JobWorker`首次固定参考库和pipeline；已固定批次及失败项重试沿用该配置。刷新历史报告不会执行当前模型。
- 文本证据已有来源作品、来源版本、查询/来源位置及语义判定信息，尚未形成两篇全文的共同阅读与定位工作区。

## 2. 方案选择与范围

考虑过三种方式：继续局部补入口；只替换页面样式；以任务为中心重组前端并补必要后端状态。前两种无法满足用户已明确的跨阶段衔接、继续训练和全文审核要求，因此本设计采用第三种。该选择依据用户本轮方向，具体布局与技术安排仍属本设计提案。

继续使用Vue、Element Plus、ECharts、现有Java/Python服务。保留检测、清洗、训练及入库的可复用实现。新增范围限于实际流程状态、模型父子版本、已完成模型继续训练、复检关联与来源全文读取所必需的后端修改；不建设通用流程引擎，不重写无关检测算法或数据库。

页面范围：登录、各角色首页、数据中心、训练、模型管理与预测、发布/回退、批量入库、参考作品、共用编辑区、送审历史、审核列表/详情、系统管理、发布/来源阅读。前端风格和公共交互统一；训练流程只在相关工作人员任务中出现，不向创作者展示训练入口。

## 3. 首页及任务工作区

管理员首页提供四个明确入口：上传数据集、继续训练已有模型、新建模型训练、加入参考库。审核员显示其有权限的数据上传、质量处理和入库入口；创作者围绕写稿、检查、送审及处理结果进入工作。

点击入口建立独立流程记录，不直接启动训练或入库计算。连续重复点击须复用同一次创建请求。首页保留紧凑的进行中任务和最近任务，用户可以恢复未结束流程。

流程种类与阶段：

| 任务 | 阶段 |
| --- | --- |
| 上传数据集 | 上传与字段映射 → 评估与清洗 → 按用途入库、训练或两者分支 |
| 新建模型训练 | 选数据 → 准备样本 → 选算法与参数 → 训练 → 评价 → 试用/版本管理 |
| 继续训练已有模型 | 选起始模型版本 → 选训练数据 → 续训配置 → 训练 → 新旧评价比较 → 试用/版本管理 |
| 加入参考库 | 选清洗新闻 → 入库确认/申请 → 处理与索引 → 可用来源 |

已完成的数据处理可以复用，流程中写明“复用某版本”，不得冒充本次重新完成。新闻原稿与标签句对保持各自的数据处理规则，标签句对不进入文章参考库。

流程带在主体顶部固定位置持续可见，下面展示当前阶段内容。阶段可点击定位已完成结果或当前操作；缺少必需输入的后续阶段不可跳过验证。若入库和训练均需要，两条分支分别显示状态，不能把它们画成强制依次完成的同一条链。

最小持久化流程记录保存创建者、部门、用途、当前阶段及数据版本/准备任务/父模型/运行任务/模型版本/入库批次身份。状态由真实任务推导；现有SSE和任务轮询提供实时更新。刷新、后退、退出再登录或切换流程后可恢复，切换账号不能继承其他账号的当前流程。旧链接仍可打开精确记录，并进入相应工作区。

## 4. 按钮与紧凑布局规范

- 每个阶段只突出一个主要动作，放在固定操作区；任务计算期间变为进度及必要的取消入口，完成后变为明确的后续动作。
- 移除顶部、卡片、流程图下方多处重复的“下一步/继续/前往同一页面”。流程节点承担阶段定位；统一的返回入口负责回到当前任务概览。直接进入列表的用户仍能创建或恢复流程。
- 按钮文案写具体动作，例如“保存清洗版本”“开始训练”“查看评价”；不使用没有对象的“下一步”。内部导航视觉统一为直角按钮，真正的来源网址和下载保留各自语义与明确样式。
- 标题区与操作区紧凑；桌面内容间距以12—16px为主，面板内边距16px左右，替换当前重复大留白。正文阅读区保持必要行高，不为压缩页面牺牲可读性。
- 列表与详情分开，当前任务先于历史列表；参数/日志/技术编号使用折叠或抽屉，不删除已有参数。多任务仅展示所选任务的完整曲线。
- 图表按数据质量、训练、评价组织为可切换区域，桌面通常两图一行，常规高度约240—280px；不把所有阶段图表纵向堆叠。关键指标先摘要，详情按需展开。真实运行曲线继续实时更新。
- 表格保留搜索、筛选、输入页码跳转、自定义每页条数；图表保留hover/缩放，不增加图表导出。空结果使用简短状态和相关操作，不放大块空图或免责声明文字。
- 固定导航、流程带与抽屉支持键盘焦点；窄屏折叠导航及双栏，不出现无法到达的按钮。

## 5. 已完成模型的继续训练与版本

区分“中断恢复”“继续训练”“重新训练”。中断恢复沿用原检查点及原配置；继续训练从已完成模型的权重开始，允许新的训练轮数、学习率和合格的新数据；重新训练从算法的基础初始化开始。

CNN、BiLSTM、BERT支持真正的继续训练：选择固定父版本，读取其已保存模型/编码器，加载父权重，新任务创建独立训练状态。原检查点恢复功能保持，不能拿其严格同身份校验去冒充新数据继续训练。

CNN/BiLSTM的词表、嵌入及网络维度必须兼容；新词覆盖作为数据检查指标。若需要扩充词表，保留旧词索引及旧嵌入，只初始化新增部分，记录编码器变更。BERT继续使用父版本兼容的tokenizer与网络结构。影响结构的参数不可在普通续训表单中随意改变；学习率、附加轮数、批量等有效参数可以配置。

LR/SVM/RF继续使用当前实现的完整重新拟合方式，在同一逻辑模型下生成新版本；界面动作称“用新数据重新训练”，不标成继承旧权重的增量训练。一个数据集仍可训练多模型、多版本。

模型管理按逻辑模型聚合，内部列出v1/v2及父版本；新任务与工件独立存放，旧版本不覆盖。版本记录训练模式、起始模型/工件哈希、数据和划分、参数、任务及评价。现有模型迁移成首版本，不丢失原modelId、报告或发布关联。

继续训练可以组合原训练数据和新训练数据，避免仅训练新材料导致旧任务表现退化；不得把原验证/测试来源挪回训练。检查父模型历史划分与新数据的来源/近重复交叉，发现测试污染要隔离或使用独立评价材料。

新旧版本必须在共同且与双方训练材料隔离的评价集上比较。指标、混淆矩阵和错误样本显示变化；不能把不同测试集的数字当成改进幅度。保留原活动版本，由管理员明确发布新版本，不因训练完成自动切换。这里仍区分句对预测版本与整篇来源审核配置，不把两种用途混称。

### 5.1 续训版本进入实际稿件审核

设计可实施性检查确认一项重大缺口：若仅实现网页句对续训，实际整篇复检仍可能使用原有固定BERT或独立v3工件，无法满足用户通过继续训练改善实际检出的目的。因此用户已确认将以下链路纳入本轮范围，须实际接入评分器与审核配置。

本轮优先接入与当前中文BERT句对架构、标签及编码方式兼容的已训练/续训BERT版本，作为整篇候选片段的语义评分器。保留现有检索、句段对齐、引用核对和证据聚合，新增适配入口，不把分类模型当成检索编码器，也不把它假称为BGE/M3正式工件。其余算法继续提供已具备的句对实验/预测，未完成整篇适配的版本不出现“用于整篇审核”的启用操作。

完整路径为：BERT父版本 → 真实权重继续训练 → 句对评价及整篇开发评价/阈值校准 → 登记兼容正文审核配置 → 管理员发布 → 同一送审稿按当前配置复检。训练结果页在同一任务流程内显示可用的后续阶段，不要求用户再到多个管理页猜测对应操作。

正文配置绑定具体模型版本、模型和tokenizer文件哈希、适配器版本、分数含义、校准/聚合配置及评价记录。检测服务实际加载该工件并校验身份后才允许发布；报告保存实际使用身份，旧配置仍能读取和追溯。若检索特征未改变可复用兼容索引，特征身份确有变化才重建，不能只按模型名字认定兼容。

用已有隔离的整篇改写、零碎局部复用、多来源及正常新闻材料评价，记录来源命中、实际提示和正常稿误报。验证同一稿件的新复检确实使用续训工件；指标是否改善以实际对照为准，不把加载成功或句对F1提高写成整篇效果提升。若新版本未达到发布条件，流程停在待改进/待评价状态，保留旧版运行，不自动上线。

## 6. 审核工作区与来源全文

审核页上方使用紧凑结论条：当前检测结论、涉及来源、有效证据范围、检测时间及使用版本。字面重复字符/字面覆盖/最长字面片段不再作为通用大号卡片；语义复用没有字面匹配时，这三个零值仅保留在默认收起的技术详情中。

主区域为两篇全文对照：左侧不可变送审正文，右侧选中来源的对应历史全文。右侧标题区切换来源及显示来源信息；两侧点击证据定位对应范围。证据清单使用紧凑列表/可展开区域，展示片段关系、原因与必要分数，不再把每个候选都铺成等高大卡片。图片、OCR、语法及图文关联沿用同一份稿件和一致的工作区结构。

来源全文必须按该证据的sourceRevisionId读取，不能替换成最新修订；接口核验当前操作者可以读取相关稿件报告且该来源确实出现在所选检测证据中。原始网页链接作为补充。OCR来源按当时文字和对应图片展示，不伪装成普通文章。

审核决定保留独立且明确的区域，查看证据时也能到达；复检不能改变已有人工决定。页面不再嵌套多个高占比滚动区，以主体阅读滚动为主；对照定位可联动，避免强制同步不同长度文章的滚动百分比。

## 7. 疑似复用的判定和显示

默认区分三类：达到证据规则的“疑似复用”（黄色文字、图标和背景强调）；被正确覆盖的“已标注引用”（保留证据）；未达到判定条件的“相近片段”（作为次要候选默认收起）。最终是否通过由审核员作出决定。

对用户提出的“强相似或多处零碎改写”分别处理：

- 单处高质量且有效长度充分的强匹配，可触发对应来源的疑似复用。
- 多处不同位置的有效相似片段，按合并后的文字覆盖、支持片段及对应证据综合触发；不能只因每一片段较短就全部忽略。
- 重叠窗口先合并去重，重复参考版本按同一原作归并，不能靠重复检索结果凑支持数量。独立同事件报道、通知模板、人名校名和正确引用仍参与误报控制。
- 模型分数和聚合阈值由现有开发评价确定，记录配置版本；不直接把某个未经校准的BERT分数当成通用概率阈值，也不只为演示把所有相近候选改成黄色。

用户先看到结论及简短理由，例如“疑似复用 · 多处改写对应同一来源”；涉及文字/覆盖只显示由真实位置合并计算的数值。点击即可看到两篇全文的对应位置。字面复制和语义改写可以显示各自类型，不依赖字面非零才给语义警告。

复用现有优化后的判定实现，优先核对原始判定字段到前端标签的一致性；只有真实判定仍漏掉对应改写时再修正后端聚合规则。旧样本中的R01、多来源小段拼接及正常稿对照复用，做有限的有针对性验证，记录实际变化。

## 8. 按当前配置重新检测

审核详情保留一个“按当前配置重新检测”入口，替换当前分散的刷新/重复检测入口。查看完整检测历史通过一个报告选择器完成；运行时显示该次进度，原有结果可切换查看。

对同一不可变送审快照，通过现有submission checks能力建立新的检查记录；来源库、实际使用的配置/发布版本、时间和输入哈希保存到新记录。新检查固定执行时选择的配置，任务中途不会因管理员发布新版本而混用结果。原始送审批次、旧报告、稿件版本及审核决定不被覆盖。

完成后默认查看本次复检，允许选择原送审检测对照；不要求重新上传、另找文章或重新送审。同一输入下正在执行的同一次检查复用，按钮运行中不可重复启动。保留失败反馈；“沿用原配置重试”若确有需要放到历史任务详情，不能与当前配置复检混成两个相同主按钮。

复检范围以实际完成的项目显示：正文/图片复用、OCR及语法/图文模块的记录要绑定同一输入。某模块未执行不显示成完成；部分失败不能被总结果掩盖。旧配置不可复现时保留历史结果，不能偷偷用新模型覆盖旧名下结果。

## 9. 验证、交付及保留项

只做与本轮相关的必要验证：流程身份恢复及权限、真实父权重加载及参数更新、保存重载、训练/测试隔离、复检旧记录不变、来源全文版本和高亮、阈值/多片段/正常稿的代表性检查。保留现有检查，不扩展成大量镜像实现的测试。

用现有小规模演示数据完成一次真实的新建训练、已完成神经模型继续训练及同一评价集比较，证据包括父子工件身份与真实权重更新，不能用“复制参数后重新训练”替代。随后按管理员数据/训练/入库→创作者图文检查与送审→审核员全文比对及当前配置复检走查；不擅自给出通过审核决定。

阶段顺序：统一样式/任务壳和按钮清理 → 模型继续训练及版本 → 全文审核/复检/判定展示 → 全流程走查与收尾。必要的后端接口随对应阶段实施；每阶段报告实际完成、剩余工作和预计耗时，并精确同步GitHub既有codex分支。若工作跨度大，任务记录和代码状态作为恢复依据，不能重复实现已完成部分。

本轮结束前还须完成5.1节的兼容BERT到实际整篇评分发布链路；不能在“继续训练及版本”完成后把它无声留作未来扩展。具体接口、适配和开发校准步骤已在实施计划中单列。

历史报告、旧配置、正式训练规模、未来扩展预留和角色权限保留；正式样本准备继续暂停。没有新环境/依赖的默认授权，确需安装或发生环境冲突先请示。设计确认前不改业务代码、不切换模型、不启动训练；确认后执行计划不能将数据准备或代码实现写作效果验收完成。

## 10. 官方设计参考与本项目的取舍

10月31日已检索并阅读以下官方资料。参考交互和管理方式，继续用现有Vue/Element Plus实现；本次没有下载或安装这些产品，也没有把React组件直接引入Vue项目。

- [PatternFly Wizard设计指南](https://www.patternfly.org/components/wizard/design-guidelines/)：参考可回访的阶段导航、突出当前步骤、单一主要操作及尽量减少阶段内长滚动。采用任务顶部固定流程带，并按本项目的实际数据分支调整，不照搬其默认“Next”文案。
- [PatternFly Actions](https://www.patternfly.org/patterns/actions/)：参考按影响范围安排操作、把次要动作收纳到菜单。用于清理重复跳转按钮和分清页面操作与记录操作。
- [MLflow Model Registry Workflows](https://mlflow.org/docs/latest/ml/model-registry/workflow/)：参考同一逻辑模型的多个版本、关联训练运行及单独管理部署选择。映射到现有模型、训练和发布表，不为此新增MLflow服务或数据库。
- [Label Studio Pairwise Classification](https://labelstud.io/templates/pairwise_comparison)：其模板支持把两个文本对象放入同一比较任务。借鉴共同阅读/比较的思路；两篇全文并排、历史版本与位置高亮是本项目自己的具体设计，不宣称该模板直接提供洗稿审核。

可实施性检查：新上下文只读检查发现的唯一重要遗漏为“续训版本是否进入实际整篇审核”，已通过5.1节明确本轮提案范围及兼容边界；这仍是待用户确认的新增安排，不代表用户已授权安装依赖或执行模型切换。
