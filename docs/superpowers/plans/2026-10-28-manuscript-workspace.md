# 共用稿件、片段引用、语法与图文检查实施

依据已批准主计划及片段引用设计；沿用功能分支。用户最新要求以功能为先，仅做构建和必要核心检查，完整回归后置。

1. 保留父编辑器，三个检测面板通过query切换，正文和未保存状态不卸载。增加兼容schema2的citation mark与来源对象，schema1仍只读/可编辑兼容。
2. 站内来源搜索/部门筛选/分页、作品身份与版本校验；站外URL只记录声明。后端从实际富文本重算Unicode范围；检测后额外计算引用覆盖，不覆盖原始模型证据。
3. 新增稿件检查持久任务：快检规则、Qwen CPU语法建议、Chinese-CLIP CPU相关段落及OCR事实字段对照；复用既有权重/隔离环境/OCR，不抢后台生成GPU。结果绑定稿件快照，修改后标记旧结果，不能回写错版本。
4. 编辑器可定位/采用/忽略语法建议；逐图显示语义分数、对应段落和OCR冲突。审核页读取不可变送审快照进行同类检查，并展示引用核对。
5. 必要核验：保存/读取schema1/2、范围与同作品引用、错来源/部分覆盖、核心规则与真实模型调用、API与构建；部署时先保存后台生成检查点，再以同配置继续，不丢已处理结果。

Chinese-CLIP项目内下载已获用户授权（本轮），固定官方版本及哈希；不安装新依赖。模型效果校准和独立正式评价仍按主计划后续完成，不将原始相似度当成事实冲突或准确率。

实施资源调整：本机总内存15.4GiB，暂停生成后可用约5.8GiB，无法满足Qwen CPU加载所需8GiB余量。语法模型在CPU余量足够时使用CPU，否则复用已有CUDA和工作台计算锁，至少6.5GiB空闲显存；后台训练/生成或在线检测占用时持久等待、可取消，不抢占进程。Chinese-CLIP仍仅CPU。此调整不安装依赖，不改变训练材料规模。
