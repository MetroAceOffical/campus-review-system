# 需求范围

范围更新：2026-10-26；当前实现记录仍依据10月24日核查。整合原需求 V0.1、已确认期中设计与当前实现。阶段安排只决定实施先后，未完成的原核心目标继续保留。

期末已确认以检测能力提升为主，业务完善为次，具体顺序为：文字常见改写主攻、图片搬运第二重点、图文相关性与有明确证据的矛盾检查作为条件性新增。文字主攻保留主要信息、篇幅大致相近的整篇重新措辞，摘要／概括单列，局部、多来源复用与正常稿误报同步评价。图文一致性不挤占文字与图片主线，当前仍未正式接入或通过质量验收。本页维护需求，训练及系统接入集中见 [期末细化设计](技术设计.md#期末细化设计)，评价规则与状态见 [验收与后续工作](验收与后续工作.md)。

本节汇总已确认目标与交给技术评估的要求，不宣称已达到效果，也不指定模型、算法、采集实现或训练参数。

| F-B01 | 次要增量 | 仅补有助于使用检测结果和完成演示的业务流程 | 具体增量在检测可行性回传后选定，不默认补齐完整毕业设计功能 |

### 数据和人工核查要求

- 可以增加公开任务数据、本校与其他高校文章，也可制作经核查的受控改写；采集数量服务于场景覆盖，不作为成果本身。
- 训练、开发和最终测试按原作、事件与近重复簇隔离；本校为主要验收场景，最终测试不用于选择方法和调参。
- 首轮评价规划为72篇查询稿，开发24篇、最终测试48篇，覆盖两类整篇改写、局部／多来源、复制、同事件正常稿、通知模板六类；该数量不是训练集规模或质量保证。
- 用户可核查样本类型、来源及证据，先用开发12篇估计实际工作量；不要求用户手算指标或逐条核查全部训练数据。
- 未经完整人工核查的标签必须注明构造或抽查身份；不能把所有 AI 生成标签写成人工金标。

### 交付边界与需要技术对话回答的问题

1. 需求侧保持整篇常见改写、局部／多来源与误报同时评价，不接受只降低门槛、扩大采集或增加模型数量作为能力提升证明。
2. 技术对话应提出能满足上述目标的路线、所需数据与人力、资源及工期，说明哪些目标可在期末完成、哪些仍有风险，不以复用当前模型为前提。
3. 数值验收目标由可行性回传后共同确认，并在最终测试前固定。不能根据最终成绩倒改标准；本节不把旧“一天修复”的建议数字直接升级为期末门槛。
4. 交付需包含真实结果、期中／期末同口径对比、失败和限制；工程可用、模型调用、质量改善分别下结论。
5. 期中训练、报告和历史失败保留；期末新证据另外记录。尚未验证的候选不写成正式实现，图文一致性不达条件时如实保留未完成。

本节由本对话维护需求；具体模型选择、数据来源可用性、训练实验、性能验证与实现交由用户安排的另一对话。本轮不启动这些工作。

## 目标与原则

面向南京传媒学院部门、教师和学生组织的图文投稿，在有限参考库中提供文字复用、图片相似及图片文字证据，由人工作出审核决定。常见同义替换、语序/句式改写、段落重排属于原核心文字目标，当前质量未通过，不能重新归为扩展。

模型不自动通过、退回、拒绝或下架。相似不等于侵权，未匹配不证明原创；填写来源、同组织或有转载许可均不免检。检测、决定、反馈和来源必须对应具体不可变版本，删除或停用不破坏历史身份。图文一致性是原目标，当前期中未接入。

| 模块 | 当前行为 |
| --- | --- |
| 账号/组织 | member1、member2各属一个组织；reviewer、admin角色互斥；真实会话与服务端权限 |
| 编辑 | 标题；段落、二/三级标题、加粗、斜体、列表、引用、链接、撤销重做；图文按顺序保存 |
| 图片/来源 | JPG/PNG/静态WebP；插入、移动、替换、删除、图注；每图原创/引用，引用链接必填；正文支持多个全文来源 |
| 草稿 | 手动保存、revision冲突保护、保存失败/重登保留编辑、离页保护；草稿可未填完整来源，送审须完整校验 |
| 正式送审 | 使用编辑器当前内容创建快照；上传未完不送审；同次请求幂等，退回修改后重提新版本 |
| 检测 | 正文、逐图相似、逐图OCR及文字检索独立；不适用、失败、空识别与质量限制分别显示 |
| 人工决定 | 通过、退回、拒绝；后两者原因必填；只处理当前有效版本一次；人工先决定后检测仍继续 |
| 发布/参考 | 通过版本发布并异步入库；管理员单篇导入、分项重试、启停待切换；手动参考不生成发布稿 |
| 实验 | 管理员只读查看六模型、20配置和真实训练历史；刷新不训练 |

| 角色 | 可访问范围 |
| --- | --- |
| 投稿成员 | 本组织草稿、送审历史、处理原因、检测进度；不能读取正式报告 |
| 审核员 | 已送审内容、正式证据、失败项重试和人工决定 |
| 管理员 | 参考管理、冻结实验；不因管理员身份取得正式报告权限 |
| 所有登录用户 | 已发布快照；发布页不泄漏内部报告与处理原因 |

草稿可编辑/送审/删除；待审只读；退回可修改重提；通过可读发布版；拒绝结束该稿正常重提。非草稿不开放删除。当前人工决定后的后补报告不发发布后疑点提醒。

输入上限为标题200码点、正文10,000码点、六图、每图10MiB/20MP/最长边8000px、来源URL2000字符。实际值读取配置，超限不静默截断或缩小原文件。

## 效果与数据要求

文字需同时检查复制、局部复用、多来源、常见改写，以及同事件独立报道、固定通知和公共表述误报。图片检查原图及缩放/压缩/保留较多主体的裁剪/加字/水印/调色，保留同场景不同照片与公共标识难负例。OCR覆盖中英混排及模糊、小字，保留空识别和覆盖不足提示。

合理引用或授权复用在内容层仍是复用，是否允许发布由人工判断。参考作品、训练样本、场景诊断与人工反馈分开；按原作/事件/近重复簇隔离训练、开发和测试，公开可见不自动取得训练或再分发许可。新作品只更新索引，不自动训练。

10月26日用户进一步明确：文章不足可继续采集，公开数据不足由执行者查找、下载并训练；停止围绕少量原作反复要求人工复核。后续数据清洗、来源/事件簇隔离、标签分层和指标复算由流程承担，不以用户再次核查作为启动条件。主要信息整体对应而仅重新措辞属于需提示的内容复用，不要求具有独特观点，也不因独立发布而自动成为正常稿。

本轮细化设计按5,000篇校园原文、100,000—200,000条有效训练记录、400篇开发/1,200篇最终查询安排，使用混合召回、语义检索训练与重排LoRA任务适配。这些为执行默认目标，尚非完成事实或教师标准；本校为主要应用场景。已取得三份公开文件，原始记录105,084条，任务与标签不同，不能全部作为复用金标。来源、模型、清洗规则、资源和阶段预留见 [期末细化设计](技术设计.md#期末细化设计)。参考原作可进入检索库，测试查询及同源变体不得参与训练和调参；机器构造、自然来源和人工标签分别报告。

## 扩展与非目标

深度重写/思想层面复用、极小局部或拼图复用、批量参考导入、在线训练及模型切换管理属于扩展。全网查重、英文长文/跨语言洗稿、自动版权裁决、社区互动、多审核员分配、实时共同输入和转载版本联动不在已承诺范围。
